# Still Building the Same Report by Hand? A 6-Step Automation Handoff

## Overview
Use this educational handoff before automating a recurring business report.

## Learning Objectives
The viewer will understand:
1. How to document a recurring report before automation.
2. Where human ownership and review remain necessary.
3. What minimum evidence should accompany a release decision.

---

## Section 1: Name the decision
**Key Concept**: Start with the business decision and accountable owner.

**Content**:
- Write the decision this report supports and the person who owns that decision.

**Visual Element**: Numbered node with decision signpost and owner doodle.

**Text Labels**:
- Headline: "1 · Name the decision"
- Labels: "Decision", "Owner"

---

## Section 2: List the sources
**Key Concept**: Document approved sources and access ownership.

**Content**:
- Record each approved source, its owner, update timing and access path.

**Visual Element**: Connected source cards feeding a small report sheet.

**Text Labels**:
- Headline: "2 · List the sources"
- Labels: "Approved source", "Owner", "Timing", "Access path"

---

## Section 3: Define the rules
**Key Concept**: Make report logic inspectable in plain language.

**Content**:
- Write the calculation, filter, grouping and exception rules in plain language.

**Visual Element**: Handwritten rule sheet with four highlighted rows.

**Text Labels**:
- Headline: "3 · Define the rules"
- Labels: "Calculation", "Filter", "Grouping", "Exceptions"

---

## Section 4: Mark the checks
**Key Concept**: Keep accountable human review and evidence.

**Content**:
- Identify who reviews the output, what they check and what evidence is retained.

**Visual Element**: Reviewer with checklist and evidence folder.

**Text Labels**:
- Headline: "4 · Mark the checks"
- Labels: "Reviewer", "Checks", "Evidence"

---

## Section 5: Set the fallback
**Key Concept**: Plan for unreliable or conflicting inputs.

**Content**:
- Define what happens when data is missing, late, duplicated or inconsistent.

**Visual Element**: Branching detour around four warning cards.

**Text Labels**:
- Headline: "5 · Set the fallback"
- Labels: "Missing", "Late", "Duplicated", "Inconsistent"

---

## Section 6: Choose the release gate
**Key Concept**: Compare outputs before authorized release.

**Content**:
- Run the automated and manual versions together; release only after the authorized owner accepts the comparison.

**Visual Element**: Manual and automated report sheets converging at an owner-controlled gate.

**Text Labels**:
- Headline: "6 · Choose the release gate"
- Labels: "Manual", "Automated", "Compare", "Owner accepts"

---

## Data Points (Verbatim)
### Key Terms
- **Minimum handoff record**: decision · decision owner · approved sources · source owners · update timing · calculation rules · exception rules · reviewer · retained evidence · fallback · comparison period · release owner.
- **Boundary**: Educational workflow-design material only — not accounting, financial, legal, compliance, security, privacy or production advice. No client result, certification, ranking, saving or guarantee is claimed.

---

## Design Instructions
### Style Preferences
- Hand-drawn educational treatment on warm cream paper.
- Deep charcoal text with macaron blue, mint, lavender and peach zones.
- Coral emphasis only for warnings and the release gate.

### Layout Preferences
- Horizontal linear progression with six numbered nodes and clear arrows.
- Compact minimum-record strip along the bottom.

### Other Requirements
- Landscape 16:9.
- English.
- Keep every label readable at social-card size.
- No statistics, client claims, logos or certification marks.
