Trust & data handling

Start with the minimum information needed.

The website fit review is deliberately separated from any diagnostic evidence transfer. Scope, access, purpose, retention and deletion must be agreed before sensitive material is supplied.

Public-form boundaryNo billing files through the website.

Do not send cloud exports, invoices, credentials, customer identifiers, architecture files or other confidential material through the fit-review form or ordinary email.

Website enquiry handling

What the public form does—and does not do.

01

Minimal fields

Name, work email, company, role, website, primary concern and optional non-sensitive context.

02

Cloudflare processing

Website requests are processed through Cloudflare infrastructure and may be stored in a restricted Cloudflare KV namespace for operational follow-up.

03

Microsoft 365 notification

A confirmed form submission may trigger a Microsoft 365 notification to the configured company mailbox.

04

First-party measurement

Allowlisted events may record page and conversion activity without transmitting form-field values in analytics events.

05

No file upload

The fit-review form intentionally provides no file-upload mechanism.

06

Confirmed success only

The interface displays a reference only after the server confirms durable receipt.

If an engagement proceeds

A separate evidence boundary is required.

The appropriate model depends on scope, sensitivity, systems, geography and contracting. The website does not pre-authorize access.

Purpose and scope

Document which accounts, periods, workloads, data fields and decision questions are included or excluded.

Client-controlled access

Prefer export-based, masked, redacted or read-only approaches where appropriate. Production change authority is not part of the diagnostic.

Transfer route

Agree an authorized transfer and storage route before evidence is supplied. Ordinary public forms and unsolicited email attachments are excluded.

Retention and deletion

Define how long diagnostic material is needed, who may access it and how deletion or return will be handled after the purpose ends.

Evidence limitations

Missing, stale, aggregated or unreliable data remains visible in the conclusion and may limit which actions can be qualified.

Responsibility boundary

Trust comes from explicit limits—not unsupported assurance.
