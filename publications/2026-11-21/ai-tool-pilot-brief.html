Before You Buy an AI Tool: A 6-Box Pilot Brief

A safe educational brief to define a small, reviewable pilot before choosing an AI tool.

Six-box pilot brief

BoxAreaSafe instructionRecord
1Business taskName one task, its current owner, the trigger that starts it and the output that marks it complete.TASK · OWNER · TRIGGER · OUTPUT
2Evidence baselineRecord current time, error, rework or queue evidence using a consistent method. If no baseline exists, observe first.TIME · ERROR · REWORK · QUEUE · OBSERVE FIRST
3Data boundaryList the data the pilot may use, the data it must not use and the approved storage or access path.ALLOWED · RESTRICTED · APPROVED PATH
4Human controlIdentify who reviews outputs, what requires approval and when the workflow must stop or return to a person.REVIEW · APPROVAL · STOP · RETURN TO PERSON
5Pilot measureChoose one observable process measure and one quality check. Define how both will be recorded.PROCESS MEASURE · QUALITY CHECK · RECORD BOTH
6Exit decisionAt the review date, choose: proceed, revise or stop. Record the evidence and owner for the next decision.PROCEED · REVISE · STOP · EVIDENCE + OWNER

Minimum pilot record: task · owner · trigger · baseline · allowed data · restricted data · reviewer · stop condition · process measure · quality check · review date · exit decision

Quick answers

What should be defined before an AI-tool pilot?

Define the business task, evidence baseline, data boundary, human control, pilot measure and exit decision.

What if no baseline exists?

Observe first and record current evidence using a consistent method.

Does this brief recommend a particular AI tool?

No. It is educational pilot-planning material, not a procurement recommendation or performance guarantee.

Proof boundary

Educational pilot-planning material only — not a client case study, performance guarantee, security assessment, legal or compliance advice, procurement recommendation or production-change instruction.
